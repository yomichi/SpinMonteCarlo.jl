## Overview

SpinMonteCarlo.jl is a Julia package implementing Markov chain Monte Carlo solvers for finite-temperature lattice spin systems (classical: Ising, Potts, XY, Clock, AshkinTeller; quantum: QuantumXXZ).

## Commands

```bash
# Run the full test suite (uses test/Project.toml; takes several minutes — tests are statistical MC runs with MCS=10000)
julia --project -e 'using Pkg; Pkg.test()'

# Format code (style is "yas", configured in .JuliaFormatter.toml; CI checks formatting on PRs)
julia -e 'using JuliaFormatter; format(".")'

# Build documentation
julia --project=docs docs/make.jl
```

To run a single test file: `test/runtests.jl` defines shared constants (`SEED`, `SEED2`, `MCS`, `Therm`, `alpha`) that the individual test files depend on, so they cannot be included standalone. Temporarily trim the `filenames` array in `test/runtests.jl` to the file you want, then run `Pkg.test()`.

## Architecture

The package is a plugin system built on Julia multiple dispatch. The user passes a `Parameter` (alias for `Dict{String,Any}`) to `runMC` with keys `"Model"`, `"Lattice"`, `"Update Method"` (values are types/functions, e.g. `Ising`, `SW_update!`), plus physical/simulation parameters (`"T"`, `"J"`, `"MCS"`, ...).

### The runMC loop (src/runMC.jl)

1. `param["Model"](param)` constructs the model (which calls `generatelattice(param)` internally).
2. `convert_parameter(model, param)` extracts typed arguments `p...` from the Dict once, up front (type stability).
3. Each MC step: `st = update!(model, p...)` mutates the spin configuration and may return extra info (e.g. `SWInfo` cluster data); `estimator(model, p..., st)` returns a `Dict` of per-step observables, accumulated into an observable set.
4. After the loop: `binning` → `postproc(model, param, binned)`, which typically applies `jackknife` and computes derived quantities (Specific Heat, Binder Ratio, ...). Its return value is the return value of `runMC`.

Checkpoint/restart is handled in the same loop via `Serialization` when `"Checkpoint Interval" > 0`.

### Extension points (documented in docs/src/develop.md)

To add a new model, create `src/model/<Name>/` with the same four-file layout as existing models (`<Name>.jl` struct + `update.jl` + `estimator.jl` + `postproc.jl`), include them from `src/model/model.jl`, and export from there:

- **Model struct**: subtype of `Model`, must have fields `lat::Lattice` and `rng::Random.MersenneTwister`, and a constructor taking `param::Parameter`.
- **`convert_parameter`**: generate with the `@gen_convert_parameter` macro (src/API/parameter.jl); a `Function` as the size argument (e.g. `numbondtypes`) produces a vector, a non-function produces a scalar.
- **Update method / Estimator**: dispatch on the model type. `default_estimator(model, update!)` picks the estimator when `param["Estimator"]` is absent (e.g. cluster updates get `improved_estimator`, local updates get `simple_estimator`).
- **Lattices**: registered by name in the `stdlattices` dict in src/lattice/standard.jl; `generatelattice(param)` looks up `param["Lattice"]`.

### Observables (src/observables/)

Self-contained MC statistics stack: simple/binning observables accumulated via `obs["name"] << value`, jackknife resampling for error propagation through derived quantities, and `p_value` for statistical comparison. `mean`/`stderror`/`p_value` on results all come from here.

## Tests are statistical

Tests compare MC results against exact reference data in `test/ref/` (classical: transfer-matrix/exact results for fully connected graphs, generated by `exact.jl`; quantum: exact diagonalization JSON files, generated by `diag.jl`) using `p_value` thresholds. A single MC run can legitimately fail; classical tests run two seeds and require at least one to pass. An occasional isolated test failure may be a statistical fluctuation — rerun before assuming a code bug, but systematic failures across observables indicate a real regression.
